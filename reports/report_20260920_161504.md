## Summary

**Report – Main Points of the Sherlock Internship Challenge**

- **Objective** – Build a real‑time prototype that automatically identifies the interview **candidate** among all meeting participants (Zoom, Teams, Google Meet) while continuously updating a confidence score and explaining its decision. [4]

- **Key Requirements**  
  - Auto‑select the correct candidate.  
  - Maintain a dynamic confidence metric that updates as new data arrives.  
  - Handle edge cases: incorrect/changed display names, missing metadata, ambiguous situations, multiple interviewers, silent observers, etc. [5]  
  - Provide explainable reasoning (e.g., name match, speaking time, video presence, transcript alignment). [5]

- **Available Signals**  
  - Participant info: ID, display name, join/leave, webcam state, screen‑share.  
  - Audio: per‑person streams, speaking activity, duration.  
  - Video: per‑person webcam feeds.  
  - Transcript: speaker‑attributed text.  
  - External metadata: candidate name/email, calendar invite, schedule, interviewer list. [5]

- **Deliverables**  
  1. Working demo (any language/framework). [1]  
  2. 5‑10 min demo video covering architecture, approach, trade‑offs, future improvements. [1]  
  3. GitHub repo with source code, README, setup instructions, assumptions. [1]  
  4. Architecture diagram with explanation. [1]  
  5. Evaluation report (testing, edge cases, accuracy, limitations). [1]

- **Bonus Features** (if possible)  
  - Fuse multiple weak signals.  
  - Produce a confidence score.  
  - Explain selection reasoning.  
  - Continuously learn from new interview data.  
  - Operate in real time.  
  - Gracefully handle uncertainty. [1]

- **Evaluation Criteria** (weights)  
  - Problem‑solving ability – 25 % [2]  
  - Engineering quality – 20 % [2]  
  - AI/ML approach – 20 % [2]  
  - Product thinking – 15 % [2]  
  - Scalability – 10 % [2]  
  - Code quality – 5 % [2]  
  - Creativity – 5 % [2]

- **Constraints & Freedom**  
  - Any AI models, LLMs, open‑source projects, agents, cloud services allowed.  
  - Focus on practicality and real‑time performance; no predefined solution. [3]
